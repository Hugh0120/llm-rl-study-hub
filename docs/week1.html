0.1 贯穿全文的例子：让模型学习做乘法题

假设训练样本给出 prompt：

计算 17 × 23，并给出简短推理。

当前模型可能采样出两条回答：

rollout 回答 verifier reward
A 17 × 23 = 391 111
B 17 × 23 = 381 000

训练目标不是把 1 或 0 当作 token 标签，而是：

  1. 让模型自己生成回答；
  2. 用 verifier 给整条回答打分；
  3. 判断回答中每个 token 相对“正常发挥”是好还是坏；
  4. 提高好决策的概率、降低坏决策的概率；
  5. 限制一次更新的幅度，避免模型为了这批题破坏原有语言能力。

后文所有公式都会回到这个例子。看见抽象符号时，可以立即替换：

状态 s_t       = “题目 + 当前已写出的答案前缀”
动作 a_t       = 下一个 token
轨迹 τ         = 一整条回答
策略 π_θ       = 当前语言模型
reward R(τ)    = verifier 对整条回答的评分

第一章：先把 LLM 后训练写成一个 MDP

本章问题：模型生成的是离散 token，为什么仍然可以把它当作一个可优化的决策过程？

强化学习不是“有 reward 的监督学习”。关键差异是：当前动作会影响未来会看见什么状态，也会影响未来能拿到的 reward。

  • ata_tat​：策略在该状态选择的动作；
  • P(st+1∣st,at)P(s_{t+1}\mid s_t,a_t)P(st+1​∣st​,at​)：环境转移；
  • rt=r(st,at)r_t=r(s_t,a_t)rt​=r(st​,at​)：即时奖励；

一个容易忽略的点

环境转移对 LLM 通常不是难点：生成 a_t 之后，下一个状态就是把它拼到上下文里。但策略会改变训练数据本身：模型更新后，会采到不同的 token、不同的推理路径和不同长度的回答。这正是 RL 比监督微调难的根源。

对数学题 verifier，常见 RRR 是最终答案正确时的 111，否则 000。对 RLHF，RRR 往往来自 reward model。注意：即使奖励只在最后给出，每一个生成 token 都参与决定了该最终奖励。

为什么不是直接把 reward 当 label？

监督学习有固定 (x,y)(x,y)(x,y)；RL 的 yyy 来自当前 πθ\pi_\thetaπθ​。你真正要调整的是“采到这条回答的概率”，而不是把一个标量 reward 伪装成 token 标签。

第二章：REINFORCE —— 让高回报轨迹更可能出现

本章问题：不能对采样出来的 token 求导，怎样把 reward 变成模型参数的梯度？

2.1 关键技巧：log-derivative trick

目标是调整模型参数 θ\thetaθ，让高回报轨迹更容易被采到。困难在于 τ\tauτ 是离散采样结果，不能把 token id 对 θ\thetaθ 直接求导。解决办法不是“对 token 求导”，而是对产生该 token 的概率求导。

下面从目标函数逐行推导。为便于阅读，先把轨迹看成离散变量；连续情形只是把求和换成积分。

第一步：把期望写成“所有轨迹的概率加权和”

J(θ)=Eτ∼pθ[R(τ)]=∑τpθ(τ)R(τ).J(\theta) =\mathbb E_{\tau\sim p_\theta}[R(\tau)] =\sum_\tau p_\theta(\tau)R(\tau).J(θ)=Eτ∼pθ​​[R(τ)]=τ∑​pθ​(τ)R(τ).

这里假设一次策略更新期间 reward 函数是固定的，因此 R(τ)R(\tau)R(τ) 不直接依赖 θ\thetaθ。对 θ\thetaθ 求导：

∇θJ(θ)=∑τR(τ)∇θpθ(τ).\nabla_\theta J(\theta) =\sum_\tau R(\tau)\nabla_\theta p_\theta(\tau).∇θ​J(θ)=τ∑​R(τ)∇θ​pθ​(τ).

到这里的问题是：我们想用采样估计这个梯度，但式子里只有 ∇θpθ(τ)\nabla_\theta p_\theta(\tau)∇θ​pθ​(τ)，还没有概率权重 pθ(τ)p_\theta(\tau)pθ​(τ)。

第二步：由链式法则得到 log-derivative trick

对任意正概率 pθ(τ)>0p_\theta(\tau)>0pθ​(τ)>0：

∇θlog⁡pθ(τ)=1pθ(τ)∇θpθ(τ).\nabla_\theta\log p_\theta(\tau) =\frac{1}{p_\theta(\tau)}\nabla_\theta p_\theta(\tau).∇θ​logpθ​(τ)=pθ​(τ)1​∇θ​pθ​(τ).

两边乘以 pθ(τ)p_\theta(\tau)pθ​(τ)，得到：

∇θpθ(τ)=pθ(τ)∇θlog⁡pθ(τ).\nabla_\theta p_\theta(\tau) =p_\theta(\tau)\nabla_\theta\log p_\theta(\tau).∇θ​pθ​(τ)=pθ​(τ)∇θ​logpθ​(τ).

这不是一个额外假设，只是 ∇log⁡p=(1/p)∇p\nabla\log p=(1/p)\nabla p∇logp=(1/p)∇p 的移项。将它代回上一步：

∇θJ(θ)=∑τpθ(τ)R(τ)∇θlog⁡pθ(τ)=Eτ∼pθ[R(τ)∇θlog⁡pθ(τ)].\begin{aligned} \nabla_\theta J(\theta) &=\sum_\tau p_\theta(\tau)R(\tau) \nabla_\theta\log p_\theta(\tau)\\ &=\mathbb E_{\tau\sim p_\theta} \left[R(\tau)\nabla_\theta\log p_\theta(\tau)\right]. \end{aligned}∇θ​J(θ)​=τ∑​pθ​(τ)R(τ)∇θ​logpθ​(τ)=Eτ∼pθ​​[R(τ)∇θ​logpθ​(τ)].​

现在式子重新变成了一个期望，所以可以用模型实际采出的 rollout 做 Monte Carlo 估计。

第三步：把“整条轨迹的 log 概率”拆成每一步

由第一章的轨迹分解：

log⁡pθ(τ)=log⁡ρ0(s1)+∑t=1T[log⁡πθ(at∣st)+log⁡P(st+1∣st,at)].\begin{aligned} \log p_\theta(\tau) &=\log\rho_0(s_1)\\ &\quad+\sum_{t=1}^{T} \left[ \log\pi_\theta(a_t\mid s_t) +\log P(s_{t+1}\mid s_t,a_t) \right]. \end{aligned}logpθ​(τ)​=logρ0​(s1​)+t=1∑T​[logπθ​(at​∣st​)+logP(st+1​∣st​,at​)].​

对 θ\thetaθ 求导时：

  • ρ0\rho_0ρ0​ 是数据或 prompt 的来源，不由模型参数控制，所以梯度为 000；
  • PPP 是环境转移，不由模型参数控制，所以梯度为 000；
  • 只有策略 πθ\pi_\thetaπθ​ 含有 θ\thetaθ。

∇θlog⁡pθ(τ)=∑t=1T∇θlog⁡πθ(at∣st).\nabla_\theta\log p_\theta(\tau) =\sum_{t=1}^{T} \nabla_\theta\log\pi_\theta(a_t\mid s_t).∇θ​logpθ​(τ)=t=1∑T​∇θ​logπθ​(at​∣st​).

→ 把期望展开成轨迹概率加权和
→ 用 ∇log p = (1/p)∇p 把梯度改写成可采样的期望

2.2 把公式翻成工程语言

到这里我们只推导出了 原始 REINFORCE，手里只有整条回报 R(τ)R(\tau)R(τ) 或从当前时刻开始的回报 GtG_tGt​。baseline 和 advantage 还没有定义，因此先只用 GtG_tGt​ 解释更新方向：

若 G_t > 0：
    提高时刻 t 实际采样 token 的 log probability
若 G_t < 0：
    降低时刻 t 实际采样 token 的 log probability
若 G_t = 0：
    这个 token 在本次 rollout 中不给策略梯度信号

所以，当 verifier 只有 0/10/10/1 两种非负奖励时，正确回答会被鼓励，错误回答却通常只是“没有更新”，并不会被直接压低。这正是下一章要引入 baseline 的动机，但现在先不要提前使用那个结论。

如果模型最后一层输出 logits zzz，softmax 策略满足：

∂log⁡πθ(a∣s)∂zj=1[j=a]−πθ(j∣s).\frac{\partial\log\pi_\theta(a\mid s)} {\partial z_j} =\mathbf 1[j=a]-\pi_\theta(j\mid s).∂zj​∂logπθ​(a∣s)​=1[j=a]−πθ​(j∣s).

其中 1[j=a]\mathbf 1[j=a]1[j=a] 是指示函数：当 jjj 正是实际采样 token aaa 时取 111，否则取 000。这说明：

  • 对实际采样 token aaa，导数是 1−π(a∣s)>01-\pi(a\mid s)>01−π(a∣s)>0；
  • 对其他 token jjj，导数是 −π(j∣s)<0-\pi(j\mid s)<0−π(j∣s)<0；
  • 乘正权重 GtG_tGt​ 后，采样 token 的相对 logit 上升；
  • 乘负权重 GtG_tGt​ 后，方向反转，采样 token 的相对 logit 下降。

所以“提高好 token、降低坏 token”不是口号，而是 softmax log-prob 梯度的直接结果。

reward-to-go 为什么比整条回报更合理？

在时刻 ttt，动作 ata_tat​ 不可能影响它发生前的 reward。因此用完整 R(τ)R(\tau)R(τ) 给它打分，会把过去的随机性错误归因给当前动作。reward-to-go 只保留未来可受影响的部分：

Gt=rt+γrt+1+γ2rt+2+⋯ .G_t=r_t+\gamma r_{t+1}+\gamma^2r_{t+2}+\cdots.Gt​=rt​+γrt+1​+γ2rt+2​+⋯.

这不会删掉动作 ata_tat​ 能影响的任何奖励，因此梯度估计仍然无偏；它只是移除了动作不可能影响的过去奖励，所以噪声更低。这一原则叫 causality。

2.3 REINFORCE 与 SFT 的差别

两者的代码表面都像 -weight * logprob，但语义不同：

所以不能把 RL loss 当作“带一个 reward 权重的交叉熵”就结束；后面所有稳定化机制都在处理这个分布耦合问题。

2.4 回到乘法题：一次更新到底做了什么？

第二章小结：REINFORCE 解决“能不能学”，没有解决“学得稳不稳”

log-derivative trick 把不可导的离散采样，转换成可导的 log-prob 梯度。代价是梯度方差很高，而且信用分配粗糙。下一章要把“整条回答得了几分”改造成“这个 token 比当前前缀下的正常选择好多少”。

第三章：从回报到 Advantage —— 解决 credit assignment 与高方差

本章问题：REINFORCE 已经能更新模型，为什么实际训练仍然抖动得厉害，而且不知道奖励该归功于哪些 token？

3.1 为什么 raw return 不够用

上一章用 GtG_tGt​ 直接加权 log-prob。它是“从当前 token 开始，这一次采样最终拿了多少分”；单次结果会受到题目难度、后续随机 token 和奖励噪声影响，方差很大。

考虑两条回答都答对，最终 reward 都为 1：

  • 第一条是模型在简单题上本来就会的；
  • 第二条是在很难的题上偶然推对了。

如果都乘 1，更新会把第一条中本就高概率的普通 token 也强力推高。真正有用的问题是：这个动作比模型在这个状态下的正常水平好多少？

  • QQQ：此刻选定某 token 后，平均还能拿多少分；

真实的 QπQ^\piQπ 和 AπA^\piAπ 都是对许多未来 rollout 取期望，通常无法精确计算。训练时用本次观察到的 GtG_tGt​ 估计 Qπ(st,at)Q^\pi(s_t,a_t)Qπ(st​,at​)，再减去 baseline：

3.4 TD、n-step 与 GAE

只等到整条回答结束再算 GtG_tGt​ 是 Monte Carlo：依赖真实完整回报，偏差小但方差高。另一端是只向前看一步：

以两步为例，把 δ\deltaδ 展开：

GAE 不硬选一步、两步或整条轨迹，而是用 λ∈[0,1]\lambda\in[0,1]λ∈[0,1] 对不同视野做指数衰减混合。整理后得到：

这里沿用全文的编号：一条回答有动作 a1,…,aTa_1,\ldots,a_Ta1​,…,aT​，所以最后一个动作对应的 δT\delta_TδT​ 也必须进入求和。若代码用从 000 开始的下标，等价地会写到最后一个有效 token；关键不是死记上界，而是不能漏掉终止 token 的 TD 误差。

  • λ→1\lambda\to1λ→1：更接近 Monte Carlo，偏差小、方差大；
  • λ→0\lambda\to0λ→0：更接近一步 TD，方差小、但更依赖 critic；
  • 实践中常从 γ≈1\gamma\approx1γ≈1、λ∈[0.9,0.97]\lambda\in[0.9,0.97]λ∈[0.9,0.97] 开始，而不是把它们当神奇常数。

实现时通常从序列末端反向递推：

for t in reversed(valid_token_positions):
    delta = reward[t] + gamma * value[t + 1] - value[t]
    last_gae = delta + gamma * lambda_ * last_gae
    advantage[t] = last_gae
returns = advantage + value

回答真正结束处的下一状态 value 设为 000；padding token 以及跨 episode 的位置必须用 mask 排除，不能让 GAE 从下一条样本反向串回来。

3.5 LLM 场景的 advantage

若只有最终 verifier reward，原始逐 token reward 向量很稀疏：通常只有终止位置非零。GAE 会把这个终点信号向前传播，因此得到的 token-level advantage 不一定稀疏。常见选择：

  1. PPO/RLHF：训练 value head，以 GAE 得到 token 级 A^t\hat A_tA^t​；
  2. GRPO：对同一 prompt 采样一组回答，用组内相对 reward 构造基线，避免单独训练 value model；
  3. 结果奖励之外加可控的过程/格式奖励，但必须警惕模型投机 reward。

还要注意：不同前缀拥有不同 V(st)V(s_t)V(st​)，不等于 critic 精确知道“哪个推理 token 导致了正确答案”。它提供的是条件期望基线和较低方差的信用信号，不是因果解释器；只有终点奖励时，credit assignment 仍然可能很粗。

第三章小结：advantage 改善学习信号，仍没有解决数据过期

现在每个 token 都有了可正可负的 A^t\hat A_tA^t​，梯度方差也比 raw return 更低。但 rollout 是旧模型采出来的；参数更新后，数据分布立即变旧。下一章要回答：如何有限度地复用旧 rollout，同时控制新旧策略的偏移？

第四章：为什么要 PPO —— 同一批 rollout 不能随便多训

4.3 KL 为什么仍然必须监控

clip 约束的是被采样 token 的 ratio，不能严格保证整个词表上的策略分布距离小。更完整的 trust region 思路会限制：

实践中常见总损失可以写成下面的组合。其中 cvc_vcv​ 是 value loss 权重，cec_ece​ 是 entropy bonus 权重，β\betaβ 是 reference KL 的惩罚权重：

  • entropy bonus：避免过早变得确定；
  • KL to reference：不让已训练好的语言能力因奖励优化而漂移过远。

KL 惩罚常见有两条实现路径：

  1. 作为 shaped reward：rollout 时把逐 token 的 −β(log⁡πold−log⁡πref)-\beta(\log\pi_{old}-\log\pi_{ref})−β(logπold​−logπref​) 加进奖励，再用 shaped reward 计算 GAE；
  2. 作为显式 loss：优化时计算新策略与 reference 的分布级 KL，再加到总损失。

两条路线表达的是同一个“行为锚定”目的，具体实现可以不同。阅读代码时要先确认项目采用哪一条，避免把同一份 KL 惩罚既塞进 reward、又作为 loss 重复计算。单个采样 token 的 logp - ref_logp 只是 KL 的样本贡献，不保证每个 token 或每个小 batch 都非负。

在 LLM RL 中，old policy 与 reference policy 不是同一个概念：前者用于这一个 PPO batch 的 importance ratio；后者通常是 SFT 模型，用于长期行为锚定。

4.4 TRPO 与 natural gradient 要记住什么

更理论化的 trust-region 视角是：普通梯度以参数欧氏距离衡量步长，但神经网络参数的“小变化”不一定代表策略分布变化小。Fisher information 定义的 natural gradient 更关心输出分布的实际变化。

你不需要本周实现 TRPO，但应理解它和 PPO 的共同核心：限制策略函数空间中的改变量，而不是迷信参数空间中的学习率。

第四章小结：PPO 是受约束的数据复用

PPO 并不是一种全新的 credit assignment 方法。它接收第三章算好的 advantage，然后：

  1. 用新旧策略概率比修正旧数据；
  2. 用 clip 阻止单个 token 的改动继续带来收益；
  3. 用 KL 监控或惩罚整体分布漂移；
  4. 训练若干 epoch 后丢弃这批 rollout，重新用最新策略采样。

第五章：把整条链放回 LLM RL 训练循环

本章问题：前四章的概率、reward、value、advantage、ratio 和 KL，在一次真实训练迭代中按什么顺序产生？

5.1 一轮 PPO 的五个阶段

阶段一：用 old policy 采样

从 prompt 数据集采一批题目，用批内冻结的 πθold\pi_{\theta_{old}}πθold​​ 生成回答。必须同时保存：

  • tokens：实际生成的 token；
  • response_mask：哪些位置属于回答，排除 prompt 与 padding；
  • old_logp：old policy 当时给每个 token 的 log 概率；
  • ref_logp：长期冻结的 reference policy 给相同 token 的 log 概率；
  • values：critic 对每个回答前缀的估值。

old_logp 不能在训练若干步后重新计算，否则 ratio 的分母也会跟着变化，失去“与采样时策略比较”的意义。

阶段二：计算 reward

reward 可以来自：

  • 可验证任务：答案正确性、代码单测、JSON schema、工具调用结果；
  • 偏好任务：冻结的 reward model；
  • 辅助约束：格式、长度、违规惩罚；
  • reference KL：有些实现把逐 token KL 直接并入 shaped reward。

必须区分：

raw task reward       = 任务本身是否完成
shaped reward         = task reward + 格式/长度/KL 等训练塑形项
evaluation metric     = 独立评估集上真正关心的指标

三者混为一谈时，reward hacking 很难被发现。

本节后面的伪代码选择“KL 作为 shaped reward”这条路线：先在终止 token 放入 task reward，再给每个有效回答 token 加上 reference KL 惩罚。若你的实现选择显式分布级 KL loss，就不要再重复执行这一步。

阶段三：从 reward 得到 advantage 与 return

PPO 路线：

  1. 用 critic 得到 Vϕ(st)V_\phi(s_t)Vϕ​(st​)；
  2. 计算每步 TD 误差 δt\delta_tδt​；
  3. 反向递推 GAE，得到 A^t\hat A_tA^t​；
  4. 得到 critic 的训练目标 R^t=A^t+Vϕ(st)\hat R_t=\hat A_t+V_\phi(s_t)R^t​=A^t​+Vϕ​(st​)，它也常被称为 GAE 对应的 λ\lambdaλ-return；
  5. 只在有效回答 token 上对 advantage 做归一化。

GRPO 路线则常对同一 prompt 采样多条回答，用组内均值或标准差构造相对 advantage，不单独训练 critic。两者替换的是“如何得到 baseline”，后面的 ratio 与受约束策略更新思想仍相近。

阶段四：对同一批 rollout 做有限次优化

下面是加入 mask 和 advantage 归一化后的概念伪代码：

# ---------- rollout：此时 policy 在批内冻结为 old policy ----------
with no_grad():
    rollouts = sample(policy, prompts, temperature=...)
    old_logp = policy.logprob(rollouts.tokens)
    ref_logp = reference_policy.logprob(rollouts.tokens)
    old_values = value_model(rollouts.states)

task_rewards = verifier_or_reward_model(prompts, rollouts)

# 本伪代码采用 KL-as-reward：先构造逐 token shaped reward
token_rewards = -beta * (old_logp - ref_logp)
token_rewards[terminal_positions] += task_rewards

advantages, returns = compute_gae(
    token_rewards, old_values, response_mask, gamma, lambda_
)
advantages = masked_normalize(advantages, response_mask)

# ---------- optimization：只复用少量 epoch ----------
for epoch in range(num_epochs):
    new_logp = policy.logprob(rollouts.tokens)
    new_values = value_model(rollouts.states)

    ratio = exp(new_logp - old_logp)
    unclipped = ratio * advantages
    clipped = clip(ratio, 1 - eps, 1 + eps) * advantages

    policy_loss = -masked_mean(min(unclipped, clipped), response_mask)
    value_loss = masked_mse(new_values, returns, response_mask)

    # KL 已经进入 shaped reward，这里不要重复加 KL loss
    loss = policy_loss + c_v * value_loss
    loss.backward(); optimizer.step()

# 用于监控；这是 old policy 样本下的 reference KL 估计
sampled_ref_kl = masked_mean(old_logp - ref_logp, response_mask)

阶段五：丢弃旧 rollout，重新采样

优化若干 epoch 后：

  1. 当前 policy 已经不同于 old policy；
  2. 旧 ratio 开始偏离 111；
  3. clip fraction 与 KL 通常上升；
  4. 继续训练的收益变小，偏差与过拟合风险变大。

因此结束本轮，令新的 old policy ← current policy，重新生成 rollout。PPO 的训练是“采样—短暂优化—再采样”的交替过程，不是先生成一个永久数据集再训练到底。

第六章：五个最常见的误解

误解 1：PPO 就是“带 clip 的交叉熵”

不对。PPO 的本质是旧策略采样下的 surrogate policy improvement；clip 是为了控制复用旧 rollout 时的策略漂移。没有 old_logp、advantage 和 rollout 分布，只有一个 clipped cross-entropy 并不等于 PPO。

误解 2：value model 就是 reward model

不对。reward model 评价一个回答的偏好或质量；value model 预测当前策略从一个前缀继续生成的期望回报。前者定义优化方向，后者主要降低估计方差。

误解 3：reward 上升就说明模型更强

不一定。模型可能学会输出更长、钻格式 verifier 空子、利用 reward model 的漏洞，或因为 KL 太弱而丢失通用能力。必须结合 held-out verifier、人工样例和 KL/长度曲线判断。

误解 4：PPO clip 保证新旧策略一定很接近

不保证。clip 只对本批实际采样 token 的 surrogate objective 截断收益，并不是对整个词表分布施加严格约束。因此仍要监控 actual KL、ratio 分布和 clip fraction，必要时提前停止 epoch 或调整 KL 系数。

误解 5：只有最终 reward，所以每个 token 的 advantage 必须相同

不一定。raw sequence reward 确实可能只在终点出现，但 critic 对不同前缀的 V(st)V(s_t)V(st​) 不同，TD 误差和 GAE 会把终点信号传播成不同的 token-level advantage。不同数值表示“在各前缀下超出预期多少”，不保证精确识别了哪个 token 对最终正确具有因果作用。若完全没有 critic 或过程信号，才更接近整条回答共享一个组级学习信号。
