0.1 贯穿全文的例子：让模型学习做乘法题

假设训练样本给出 prompt：

计算 17 × 23，并给出简短推理。

当前模型可能采样出两条回答：

rollout 回答 verifier reward
A 17 × 23 = 391 111
B 17 × 23 = 381 000

训练目标不是把 1 或 0 当作 token 标签，而是：

  1. 让模型自己生成回答；
  2. 用 verifier 给整条回答打分；
  3. 判断回答中每个 token 相对“正常发挥”是好还是坏；
  4. 提高好决策的概率、降低坏决策的概率；
  5. 限制一次更新的幅度，避免模型为了这批题破坏原有语言能力。

后文所有公式都会回到这个例子。看见抽象符号时，可以立即替换：

状态 s_t       = “题目 + 当前已写出的答案前缀”
动作 a_t       = 下一个 token
轨迹 τ         = 一整条回答
策略 π_θ       = 当前语言模型
reward R(τ)    = verifier 对整条回答的评分

第一章：先把 LLM 后训练写成一个 MDP

本章问题：模型生成的是离散 token，为什么仍然可以把它当作一个可优化的决策过程？

强化学习不是“有 reward 的监督学习”。关键差异是：当前动作会影响未来会看见什么状态，也会影响未来能拿到的 reward。

先把下面的式子当作一张“组成清单”，不是要计算的等式。我们用 M\mathcal MM 给整个决策问题命名；花体字母 S\mathcal SS 和 A\mathcal AA 分别表示所有可能状态组成的集合、所有可能动作组成的集合。其余四项依次描述环境怎样变化、怎样给奖励、从哪里开始，以及怎样折扣未来奖励：

M=(S,A,P,r,ρ0,γ)\mathcal M=(\mathcal S,\mathcal A, P, r, \rho_0, \gamma)M=(S,A,P,r,ρ0​,γ)
  • S\mathcal SS：状态集合；sts_tst​ 是其中在时刻 ttt 真实出现的一个状态；
  • A\mathcal AA：动作集合；ata_tat​ 是策略在该状态真实选择的一个动作；
  • P(st+1∣st,at)P(s_{t+1}\mid s_t,a_t)P(st+1​∣st​,at​)：环境转移；
  • rt=r(st,at)r_t=r(s_t,a_t)rt​=r(st​,at​)：即时奖励；
  • ρ0\rho_0ρ0​：初始状态分布；
  • γ∈(0,1]\gamma\in(0,1]γ∈(0,1]：折扣系数。

一个容易忽略的点

环境转移对 LLM 通常不是难点：生成 a_t 之后，下一个状态就是把它拼到上下文里。但策略会改变训练数据本身：模型更新后，会采到不同的 token、不同的推理路径和不同长度的回答。这正是 RL 比监督微调难的根源。

1.2 轨迹分布与优化目标

先定义公式里的每个对象：

  • pθ(τ)p_\theta(\tau)pθ​(τ)：当前模型产生整条轨迹 τ\tauτ 的概率；下标 θ\thetaθ 提醒我们，模型参数一变，这个概率也会变；
  • ρ0(s1)\rho_0(s_1)ρ0​(s1​)：从题目或 prompt 分布中抽到初始状态 s1s_1s1​ 的概率；

对数学题 verifier，常见 RRR 是最终答案正确时的 111，否则 000。对 RLHF，RRR 往往来自 reward model。注意：即使奖励只在最后给出，每一个生成 token 都参与决定了该最终奖励。

为什么不是直接把 reward 当 label？

监督学习有固定 (x,y)(x,y)(x,y)；RL 的 yyy 来自当前 πθ\pi_\thetaπθ​。你真正要调整的是“采到这条回答的概率”，而不是把一个标量 reward 伪装成 token 标签。

第一章小结：我们有目标，但还没有梯度

到这里已经完成三件事：

  1. 把回答前缀定义为状态、下一个 token 定义为动作；

第二章：REINFORCE —— 让高回报轨迹更可能出现

本章问题：不能对采样出来的 token 求导，怎样把 reward 变成模型参数的梯度？

2.1 关键技巧：log-derivative trick

目标是调整模型参数 θ\thetaθ，让高回报轨迹更容易被采到。困难在于 τ\tauτ 是离散采样结果，不能把 token id 对 θ\thetaθ 直接求导。解决办法不是“对 token 求导”，而是对产生该 token 的概率求导。

下面从目标函数逐行推导。为便于阅读，先把轨迹看成离散变量；连续情形只是把求和换成积分。

第一步：把期望写成“所有轨迹的概率加权和”

J(θ)=Eτ∼pθ[R(τ)]=∑τpθ(τ)R(τ).J(\theta) =\mathbb E_{\tau\sim p_\theta}[R(\tau)] =\sum_\tau p_\theta(\tau)R(\tau).J(θ)=Eτ∼pθ​​[R(τ)]=τ∑​pθ​(τ)R(τ).

这里假设一次策略更新期间 reward 函数是固定的，因此 R(τ)R(\tau)R(τ) 不直接依赖 θ\thetaθ。对 θ\thetaθ 求导：

∇θJ(θ)=∑τR(τ)∇θpθ(τ).\nabla_\theta J(\theta) =\sum_\tau R(\tau)\nabla_\theta p_\theta(\tau).∇θ​J(θ)=τ∑​R(τ)∇θ​pθ​(τ).

到这里的问题是：我们想用采样估计这个梯度，但式子里只有 ∇θpθ(τ)\nabla_\theta p_\theta(\tau)∇θ​pθ​(τ)，还没有概率权重 pθ(τ)p_\theta(\tau)pθ​(τ)。

第二步：由链式法则得到 log-derivative trick

对任意正概率 pθ(τ)>0p_\theta(\tau)>0pθ​(τ)>0：

∇θlog⁡pθ(τ)=1pθ(τ)∇θpθ(τ).\nabla_\theta\log p_\theta(\tau) =\frac{1}{p_\theta(\tau)}\nabla_\theta p_\theta(\tau).∇θ​logpθ​(τ)=pθ​(τ)1​∇θ​pθ​(τ).

两边乘以 pθ(τ)p_\theta(\tau)pθ​(τ)，得到：

∇θpθ(τ)=pθ(τ)∇θlog⁡pθ(τ).\nabla_\theta p_\theta(\tau) =p_\theta(\tau)\nabla_\theta\log p_\theta(\tau).∇θ​pθ​(τ)=pθ​(τ)∇θ​logpθ​(τ).

这不是一个额外假设，只是 ∇log⁡p=(1/p)∇p\nabla\log p=(1/p)\nabla p∇logp=(1/p)∇p 的移项。将它代回上一步：

∇θJ(θ)=∑τpθ(τ)R(τ)∇θlog⁡pθ(τ)=Eτ∼pθ[R(τ)∇θlog⁡pθ(τ)].\begin{aligned} \nabla_\theta J(\theta) &=\sum_\tau p_\theta(\tau)R(\tau) \nabla_\theta\log p_\theta(\tau)\\ &=\mathbb E_{\tau\sim p_\theta} \left[R(\tau)\nabla_\theta\log p_\theta(\tau)\right]. \end{aligned}∇θ​J(θ)​=τ∑​pθ​(τ)R(τ)∇θ​logpθ​(τ)=Eτ∼pθ​​[R(τ)∇θ​logpθ​(τ)].​

现在式子重新变成了一个期望，所以可以用模型实际采出的 rollout 做 Monte Carlo 估计。

第三步：把“整条轨迹的 log 概率”拆成每一步

由第一章的轨迹分解：

log⁡pθ(τ)=log⁡ρ0(s1)+∑t=1T[log⁡πθ(at∣st)+log⁡P(st+1∣st,at)].\begin{aligned} \log p_\theta(\tau) &=\log\rho_0(s_1)\\ &\quad+\sum_{t=1}^{T} \left[ \log\pi_\theta(a_t\mid s_t) +\log P(s_{t+1}\mid s_t,a_t) \right]. \end{aligned}logpθ​(τ)​=logρ0​(s1​)+t=1∑T​[logπθ​(at​∣st​)+logP(st+1​∣st​,at​)].​

对 θ\thetaθ 求导时：

  • ρ0\rho_0ρ0​ 是数据或 prompt 的来源，不由模型参数控制，所以梯度为 000；
  • PPP 是环境转移，不由模型参数控制，所以梯度为 000；
  • 只有策略 πθ\pi_\thetaπθ​ 含有 θ\thetaθ。

因此：

∇θlog⁡pθ(τ)=∑t=1T∇θlog⁡πθ(at∣st).\nabla_\theta\log p_\theta(\tau) =\sum_{t=1}^{T} \nabla_\theta\log\pi_\theta(a_t\mid s_t).∇θ​logpθ​(τ)=t=1∑T​∇θ​logπθ​(at​∣st​).

代回目标函数，得到策略梯度：

∇θJ(θ)=Eτ∼pθ[R(τ)∑t=1T∇θlog⁡πθ(at∣st)]\boxed{ \nabla_\theta J(\theta) =\mathbb E_{\tau\sim p_\theta} \left[ R(\tau) \sum_{t=1}^{T} \nabla_\theta\log\pi_\theta(a_t\mid s_t) \right] }∇θ​J(θ)=Eτ∼pθ​​[R(τ)t=1∑T​∇θ​logπθ​(at​∣st​)]​

如果采样 NNN 条 rollout，期望可近似为样本平均：

∇θJ(θ)≈1N∑i=1NR(τ(i))∑t=1Ti∇θlog⁡πθ(at(i)∣st(i)).\nabla_\theta J(\theta) \approx \frac{1}{N}\sum_{i=1}^{N} R(\tau^{(i)}) \sum_{t=1}^{T_i} \nabla_\theta\log\pi_\theta (a_t^{(i)}\mid s_t^{(i)}).∇θ​J(θ)≈N1​i=1∑N​R(τ(i))t=1∑Ti​​∇θ​logπθ​(at(i)​∣st(i)​).

完整逻辑链现在是：

最大化期望回报
→ 把期望展开成轨迹概率加权和
→ 用 ∇log p = (1/p)∇p 把梯度改写成可采样的期望
→ 把整条轨迹的 log 概率拆成逐 token log 概率之和
→ 用 reward 加权每个已采样 token 的 log-prob 梯度

2.2 一条 rollout 如何变成可训练的 loss

2.1 得到的是一个期望：

∇θJ(θ)=E[R(τ)∑t∇θlog⁡πθ(at∣st)].\nabla_\theta J(\theta) =\mathbb E\left[ R(\tau)\sum_t\nabla_\theta\log\pi_\theta(a_t\mid s_t) \right].∇θ​J(θ)=E[R(τ)t∑​∇θ​logπθ​(at​∣st​)].

训练时不可能枚举所有回答，只能让模型采样一批 rollout，用样本平均近似这个期望。对第 iii 条 rollout，我们已经保存了每个位置实际生成 token 的 logp，现在还缺一个问题：第 ttt 个 token 应该由哪些奖励负责？

动作 ata_tat​ 只能影响它发生之后的结果，不能影响过去已经拿到的奖励。因此给它使用从时刻 ttt 开始的累计回报。

这个量叫 reward-to-go，记作 GtG_tGt​：大写 GGG 是回报的惯用记号， 下标 ttt 表示从第 ttt 步开始计算；它不是一个新的 reward model。 定义为：

Gt=rt+γrt+1+γ2rt+2+⋯=∑k=tTγk−trk.G_t =r_t+\gamma r_{t+1}+\gamma^2r_{t+2}+\cdots =\sum_{k=t}^{T}\gamma^{k-t}r_k.Gt​=rt​+γrt+1​+γ2rt+2​+⋯=k=t∑T​γk−trk​.

它执行的不是复杂算法，只是一条因果规则：

第 t 个 token 的训练权重
= 当前奖励 + 折扣后的未来奖励

如果奖励只在回答结束时给出，那么同一条回答中的各个 GtG_tGt​ 都由终点 reward 传播而来；若中间还有过程奖励或格式奖励，不同位置的 GtG_tGt​ 就会不同。

用 NNN 条 rollout 近似期望，并把梯度上升改写成深度学习框架使用的梯度下降，得到一个可最小化的 loss。

现在才给它命名：L\mathcal LL 表示 loss，下标 REINFORCE 表示这是刚才推导出的 REINFORCE loss；NNN 是本批 rollout 数量。因此：

2.4 回到乘法题：原始 REINFORCE 学到了什么

假设模型目前只会生成两种答案：

回答 当前概率 verifier reward
A：391 0.300.300.30 111
B：381 0.700.700.70 000

期望回报是：

J(θ)=0.30×1+0.70×0=0.30.J(\theta)=0.30\times1+0.70\times0=0.30.J(θ)=0.30×1+0.70×0=0.30.

如果本批采到 A，终点 reward 为 111，这条回答中的采样 token 获得正权重，A 的概率会上升。如果采到 B，reward 为 000，权重也是 000，这一条样本不更新策略。

反复采样后，A 一旦出现就会被增强，因此正确率仍然能够从 0.300.300.30 往上走。这说明 REINFORCE 已经解决了最基本的问题：即使正确答案不是监督标签，只要模型偶尔采到并获得奖励，也能提高它再次出现的概率。

但这个例子也暴露出两个结构性缺陷：

  1. 零分不是负反馈。 B 得到 000 时只是没有更新，不会被直接压低；
  2. 绝对分数没有参照系。 同样得到 111 分，可能是简单题上的正常发挥，也可能是难题上的罕见成功，却会得到相同权重。

如果奖励只在终点出现，整条回答中的 token 还会共享非常相似的回报信号，credit assignment 也很粗。原始 REINFORCE 因而“能学”，但样本效率和稳定性都不理想。

2.5 REINFORCE 与 SFT 的差别

两者的代码表面都包含 -weight * logprob，但数据来源与优化含义不同：

SFT 原始 REINFORCE
token 来自人类或离线参考答案 token 来自当前模型自己的 rollout
每个目标 token 通常都用正的 mask 权重 权重来自实际观察到的 reward-to-go
目标是复现给定答案 目标是改变采样分布、提高期望 reward
本轮数据不由当前模型生成 模型一更新，下一批 rollout 分布就会变化

因此 REINFORCE 不是“给 SFT 交叉熵乘一个 reward”这么简单。它的训练数据来自策略自身，reward 又带有很强的随机性；后续方法都在处理由此产生的方差、信用分配和数据过期问题。

第三章：用一条 LLM 回答算出 Value、TD 与 GAE

3.2 为什么不能只把最终得分广播给所有 token

先看跨 prompt 的问题。假设当前策略在两道题上的正确率为：

两次都答对并不代表训练信息完全相同：

  • 简单题得 1 分接近正常发挥；
  • 难题得 1 分远高于正常发挥。

如果都用 G=1G=1G=1 作为权重，策略看不见这种差别。我们需要先问：

站在当前前缀上，按当前策略继续生成，通常能拿多少分？

3.3 V(s)V(s)V(s) 不是手填的：它是一个学出来的前缀评分器

最自然的正常水平定义为：

固定当前前缀 sss，让当前策略 π\piπ 从这里继续采样所有可能回答，它们未来 return 的平均值。

课本把它叫 state value（状态价值），用 Vπ(s)V^\pi(s)Vπ(s) 表示：

Vπ(s)=Eτ∼π[Gt∣st=s].V^\pi(s) = \mathbb E_{\tau\sim\pi}\left[G_t\mid s_t=s\right].Vπ(s)=Eτ∼π​[Gt​∣st​=s].

在只有终局 0/1 reward 且 γ=1\gamma=1γ=1 时，Vπ(s)V^\pi(s)Vπ(s) 有一个很直观的读法：

从这个 prompt + 已生成前缀继续采样，最终答对的概率。

例如，同一前缀若真的重复采样 100 个后续，其中 31 个答对，那么该前缀的经验 value 约为 0.310.310.31。但训练时不可能为每个前缀单独采样 100 次，所以要让神经网络在大量 rollout 之间泛化。

Value 网络的输入和输出

用带参数的网络 VϕV_\phiVϕ​ 逼近未知的 VπV^\piVπ：

Vϕ(st)≈Vπ(st).V_\phi(s_t)\approx V^\pi(s_t).Vϕ​(st​)≈Vπ(st​).

在 LLM PPO 中，常见实现是：

  1. 把 prompt + response 输入一个因果 Transformer；
  2. 每个位置得到隐藏向量 hth_tht​；
  3. 在线性 value head 上输出一个标量：

伪代码只表达张量含义：

到这里，这个对象的作用已经清楚了，再给它课程中的常用名称： critic 就是这个 value 预测器。它可以与 policy 共享部分骨干，也可以是一份独立模型；数学角色不变。示例中出现的 0.300.300.30、0.450.450.45 等数字，都是 value_head 的预测值，不是人工指定的训练标签。

Value 网络拿什么当标签

rollout 结束后，真实 reward 已经知道，因此可以为每个前缀算出这次样本的 return GtG_tGt​。最直接的训练方式就是普通回归：

LV(ϕ)=Et[(Vϕ(st)−Gt)2].\mathcal L_V(\phi) = \mathbb E_t\left[ \left(V_\phi(s_t)-G_t\right)^2 \right].LV​(ϕ)=Et​[(Vϕ​(st​)−Gt​)2].

仍以只有终局 0/1 reward 的任务为例：

  • 一条成功 rollout 的各前缀，Monte Carlo 标签都是 1；
  • 一条失败 rollout 的各前缀，标签都是 0；
  • 同类前缀在大量成功与失败样本上反复出现，平方误差最优解就是平均成功率。

这就是 V(s)V(s)V(s) 的来源：策略负责产生后续，环境或 verifier 给最终结果，critic 用这些已发生的结果学习预测尚未发生的结果。

这里没有逻辑循环。每批数据中的训练目标来自已经结束的 rollout；目标和旧 value 在本轮优化时会 detach。策略更新后，“继续生成的平均结果”也会变化，下一轮再用新 rollout 继续校准 critic。

Reward model 和 critic 不是同一个东西

二者都可能输出标量，但问题不同：

模型 典型输入 学习目标 何时使用
reward model / verifier 通常是完整回答 这份答案质量如何 rollout 完成后产生 reward
critic / value model 每个生成前缀 当前策略从这里继续的期望 return rollout 中为每一步估计正常水平

reward model 可以说“整份答案得 0.8 分”，critic 要说“只看到这个前缀时，按当前策略继续，预计最终能得多少分”。

3.5 一步之后，最终得分预期改变了多少

若 VVV 预测准确，那么当前状态的未来价值应该等于：

写成 Bellman 一致性：

Vπ(st)=E[rt+γVπ(st+1)∣st].V^\pi(s_t) = \mathbb E\left[ r_t+\gamma V^\pi(s_{t+1}) \mid s_t \right].Vπ(st​)=E[rt​+γVπ(st+1​)∣st​].

rt+γVϕ(st+1)−Vϕ(st).r_t+\gamma V_\phi(s_{t+1})-V_\phi(s_t).rt​+γVϕ​(st+1​)−Vϕ​(st​).

这句话先读成：

看到本步 reward 和新前缀以后，对最终 return 的预期需要上调或下调多少？

课本把它叫 temporal-difference error（TD 误差），用 δt\delta_tδt​ 表示：

3.8 轨迹边界：continue_mask 到底在切断什么

反向递推不能跨过两条轨迹的边界。对执行动作 ata_tat​ 后是否真正结束，定义：

  • terminated[t] = 0：仍有属于同一条轨迹的真实后续；
  • terminated[t] = 1：生成 EOS，或环境明确判定成功/失败，轨迹真正结束。

continue_maskt=1−terminatedt.\texttt{continue\_mask}_t = 1-\texttt{terminated}_t.continue_maskt​=1−terminatedt​.

continue_mask 不是新的强化学习概念，只是一个乘法开关。乘 0 可以防止下一条 batch 样本的 value 串进当前轨迹。

真正终止不等于达到最大长度

这两个边界不能混成一个语义含糊的 done：

  • terminated：任务过程真的结束，后面没有合法 continuation，应令 continue_mask = 0；
  • truncated：只是采样器达到最大长度或时间限制而停止，任务理论上可能继续。

若截断时保留了最后一个真实观测，且 value 的定义包含其后续，就应使用该状态 value 进行 bootstrap。若业务把超长明确判为失败，则应先给出相应终局 reward，再按真正终止处理。补齐 batch 的 padding mask 又是另一件事，它只排除填充 token。

3.9 把公式变成一段不会错位的代码

对一条含 TTT 个 response token 的 rollout，准备：

  • reward[t]：执行第 ttt 个 token 后得到的 reward；
  • old_value[t]：生成该 token 前，旧 critic 对当前前缀的预测；
  • old_value[t + 1]：执行后新前缀的 value；截断时可用于 bootstrap；
  • terminated[t]：执行后是否真正终止。

old_value 之所以带 old，是因为它在 rollout 阶段算好后，本批 PPO 更新期间应保持不变。

# shapes:
# reward, terminated: [T]
# old_value:          [T + 1]

gae = 0.0
advantage = zeros(T)

for t in reversed(range(T)):
    continue_mask = 1.0 - terminated[t]

    delta = (
        reward[t]
        + gamma * old_value[t + 1] * continue_mask
        - old_value[t]
    )
    gae = (
        delta
        + gamma * lam * continue_mask * gae
    )
    advantage[t] = gae

value_target = advantage + old_value[:-1]

advantage = advantage.detach()
value_target = value_target.detach()

因为 GAE 算出的 A^t\widehat A_tAt​ 本来就是“目标相对旧 value 高多少或低多少”。给 critic 做回归时要把旧 value 加回去，恢复成绝对的 return 目标。以正确轨迹第一步为例：

3.10 到这里再把策略与 critic 合成 Actor–Critic

现在所有对象都已经出现：

  • critic：前缀预测器 Vϕ(st)V_\phi(s_t)Vϕ​(st​)，估计当前策略的未来 return；
  • advantage：actor 的有符号更新权重；
  • value target：critic 的回归标签。

最基本的两个 loss 是：

Lactor=−Et[A^tlog⁡πθ(at∣st)],\mathcal L_{\text{actor}} = -\mathbb E_t\left[ \widehat A_t\log\pi_\theta(a_t\mid s_t) \right],Lactor​=−Et​[At​logπθ​(at​∣st​)],

所谓 Actor–Critic，不是突然多出第三套训练逻辑，只是一个闭环：

  1. actor 生成回答；
  2. verifier / reward model 给 rollout 打分；
  3. critic 预测各前缀的正常水平；
  4. reward 与旧 value 构造 TD、GAE；
  5. advantage 更新 actor，value target 更新 critic；
  6. actor 改变后重新 rollout，再校准 critic。

同一批数据内，old_value、advantage 和 value_target 都应冻结。不能在每个 PPO minibatch 中一边更新 critic，一边重新计算这批样本的 advantage，否则 actor 的训练标签会在一次优化过程中漂移。

3.11 只有终局 reward 时，GAE 做到了什么、没做到什么

在数学推理任务中，常见 reward 结构是：

rt=0(t<T),rT=R.r_t=0\quad(t<T),\qquad r_T=R.rt​=0(t<T),rT​=R.

GAE 仍能产生不同的 token 权重，是因为 learned critic 会随前缀改变预测：

  • 新前缀让成功预期上升，产生正 TD；
  • 新前缀暴露错误，让成功预期下降，产生负 TD；
  • 终局 reward 纠正整条预测链；
  • GAE 再控制这种修正向前传播多远。

但必须保留边界：

  1. GAE 使用的是学到的前缀价值变化，不是人工标注的推理步骤对错；
  2. critic 不准，细粒度 credit assignment 就不准；
  3. 同一序列的所有 token 使用同一个终局分数，并不等于获得过程监督；
  4. 真正的过程监督需要过程 reward、步骤 verifier 或其他额外信息。

第二周会介绍另一条路线：对同一 prompt 采样一组回答，用组内平均表现代替 learned value baseline。那是 GR-REINFORCE / GRPO 的出发点，不要与本章的 critic 混为一谈。

第四章：同一批 rollout 为什么不能随便多训

第三章改善了每个动作的权重，却仍有一个数据问题。

第二章和第三章的推导都默认：

4.5 clip 不等于真正的距离保证

clip 只作用于样本中的动作概率比，不保证整个词表分布的 KL 一定小。因此至少监控 KL divergence。

课本把它写成 DKL(P∥Q)D_{\mathrm{KL}}(P\|Q)DKL​(P∥Q)：DDD 表示 divergence， 下标 KL 是 Kullback–Leibler，竖线两边的顺序有意义。下面第一个式子比较 old policy 与 current policy：

DKL(πold(⋅∣s)  ∥  πθ(⋅∣s)).D_{\mathrm{KL}} \left( \pi_{\text{old}}(\cdot\mid s) \;\|\; \pi_\theta(\cdot\mid s) \right).DKL​(πold​(⋅∣s)∥πθ​(⋅∣s)).

它回答：“本轮 current 离 rollout 快照走了多远？”

另一个常见 KL 是：

DKL(πθ(⋅∣s)  ∥  πref(⋅∣s)).D_{\mathrm{KL}} \left( \pi_\theta(\cdot\mid s) \;\|\; \pi_{\text{ref}}(\cdot\mid s) \right).DKL​(πθ​(⋅∣s)∥πref​(⋅∣s)).

它回答：“训练后的模型离长期 reference 走了多远？”

KL 角色 典型用途
old ↔ current 优化稳定性 early stop、调小 epoch/学习率
current ↔ reference 行为锚定 奖励塑形或额外正则

不要只写“监控 KL”而不说明是哪两份策略。

可选：TRPO 与 natural gradient 在这条故事中的位置

TRPO 直接提出一个带 KL 约束的优化问题，在局部二阶近似下得到 natural-gradient 风格的方向。PPO 用一阶优化和 clipping/KL penalty 给出更容易实现的近似。对本周主线，只需记住：TRPO 更显式地约束分布距离，PPO 更工程化，但 clip 不是数学上的硬信赖域。

5.1 一轮训练的因果顺序

步骤一：冻结 rollout 快照

箭头 ←\leftarrow← 表示“把右边当前策略的参数复制给左边的 old policy”，不是求导，也不是让两份模型以后始终同步：

πold←πθ.\pi_{\text{old}}\leftarrow\pi_\theta.πold​←πθ​.

记录每个采样 completion token 的：

  • token_id
  • old_logp
  • value
  • completion_mask

步骤二：生成并打分

对 prompt xix_ixi​：

yi∼πold(⋅∣xi),Ri=reward(xi,yi).y_i\sim\pi_{\text{old}}(\cdot\mid x_i), \qquad R_i=\text{reward}(x_i,y_i).yi​∼πold​(⋅∣xi​),Ri​=reward(xi​,yi​).

reward 可以来自人工、reward model 或 verifier。它负责评价结果，不负责预测未来。

步骤三：构造逐步 reward

终局任务最简单的版本：

ri,t={0,t<Ti,Ri,t=Ti.r_{i,t}= \begin{cases} 0,&t<T_i,\\ R_i,&t=T_i. \end{cases}ri,t​={0,Ri​,​t<Ti​,t=Ti​.​

若使用 reference KL 约束，可选两条实现路径之一：

路径 A：KL 进入 shaped reward

ki,tk_{i,t}ki,t​ 表示第 iii 条回答、第 ttt 个 token 相对 reference policy 的偏离代价；β\betaβ 控制这项代价的权重。于是任务 reward 减去偏离代价后得到 shaped reward：

ri,tshaped=ri,ttask−β ki,t.r^{\text{shaped}}_{i,t} = r^{\text{task}}_{i,t} -\beta\,k_{i,t}.ri,tshaped​=ri,ttask​−βki,t​.

随后用 shaped reward 计算 GAE。

路径 B：KL 作为单独 loss

下面公式中的三个 L\mathcal LL 分别表示 actor loss、value loss 和 KL loss； cvc_vcv​ 是 value loss 的系数，β\betaβ 是 KL loss 的系数。它们只负责调节三部分在总 loss 中的相对尺度：

L=Lactor+cvLvalue+βLKL.\mathcal L = \mathcal L_{\text{actor}} +c_v\mathcal L_{\text{value}} +\beta\mathcal L_{\text{KL}}.L=Lactor​+cv​Lvalue​+βLKL​.

两条路径的尺度和梯度语义不同。除非你明确推导过，不要同时加两次 KL。

步骤四：冻结 advantage 与 old log-prob

用 rollout 阶段保存的 value 和 reward 计算两个量：

  • A^t\widehat A_tAt​：给 actor 使用的优势估计；
  • R^t\widehat R_tRt​：给 critic 回归的 value target。这里的帽子表示估计目标；它不是环境给出的原始 reward RiR_iRi​。
A^t=GAE⁡(rt,Vold(st)),R^t=A^t+Vold(st).\widehat A_t=\operatorname{GAE}(r_t,V_{\text{old}}(s_t)), \qquad \widehat R_t=\widehat A_t+V_{\text{old}}(s_t).At​=GAE(rt​,Vold​(st​)),Rt​=At​+Vold​(st​).

进入 PPO epoch 后，advantage、value_target、old_logp 都作为常量使用，不能随着每个 minibatch 重新反向传播。

步骤五：有限复用 rollout

for epoch in range(K):
    for mb in minibatches(rollout):
        new_logp = policy.logprob(mb.tokens)
        ratio = exp(new_logp - mb.old_logp)

        unclipped = ratio * mb.advantage
        clipped = clamp(ratio, 1-eps, 1+eps) * mb.advantage
        actor_loss = -masked_mean(min(unclipped, clipped), mb.mask)

        new_value = critic(mb.states)
        value_loss = masked_mean(
            (new_value - mb.value_target) ** 2,
            mb.mask,
        )

        loss = actor_loss + value_coef * value_loss
        loss.backward()
        optimizer.step()
        optimizer.zero_grad()

步骤六：丢弃旧数据，重新采样

完成 KKK 个 epoch 后，这批 rollout 的复用到此为止。下一轮必须：

πold←πθ\pi_{\text{old}}\leftarrow\pi_\thetaπold​←πθ​

并生成新数据。PPO 是受限制的短期复用，不是把 rollout 变成永久离线数据集。
