从策略梯度到 PPO

从一条 LLM 回答如何生成和评分开始，逐步建立按结果更新 token 概率、估计相对表现并限制更新幅度的完整训练逻辑。

第一周：从“给回答打分”到“稳定更新语言模型”

适用对象：熟悉深度学习、Transformer 和基本概率论，但没有系统学过强化学习的算法工程师。

正文可以脱离 slides 独立阅读。第一章不预设强化学习术语；公式中的符号会在公式之前逐个解释。

本周只研究一条训练链：

语言模型自己生成回答，外部系统给回答打分；我们根据这些分数调整模型，同时限制一次更新不要走得过远。

各章依次回答：

  1. 一条回答是怎样逐步生成、怎样被评分的？
  2. 最终分数怎样改变已生成 token 的概率？
  3. 怎样判断某个 token 的表现高于还是低于正常水平？
  4. 怎样有限复用同一批回答，同时避免模型变化过大？
  5. 这些计算在一次真实训练迭代中按什么顺序发生？

贯穿本周的 prompt 是：

计算 17 × 23，并给出简短推理。

这里的 verifier 是自动判题程序：它读取完整回答并检查最终结果是否正确。

模型可能生成：

回答 verifier 评分
17×20=340；17×3=51；所以答案是391。 1
17×20=340；17×3=41；所以答案是381。 0

我们不会把 1 或 0 伪装成 token 标签。真正的问题是：怎样让第一条回答以后更容易出现，让第二条回答以后更不容易出现？

第一章：模型怎样自己生成答案并从得分中学习

本章不从强化学习术语开始，只跟着一次语言模型生成过程走到底。读完后，你只需要能回答：

  1. 模型在每个生成位置控制什么？
  2. 一整条回答的概率为什么是逐 token 概率的乘积？
  3. verifier 的一个最终分数怎样变成训练目标？
  4. 为什么这个问题不是普通的有标签监督学习？

1.1 先看一轮训练实际发生了什么

忽略算法名称，一轮最小训练过程只有四步。

第一步：取一道题。

从训练题库取得一个 prompt：

计算 17 × 23，并给出简短推理。

第二步：让当前模型自己生成。

模型不是读取标准答案，而是根据自己的 next-token 概率逐步采样。一次可能生成正确回答，另一次也可能生成错误回答。

第三步：生成结束后评分。

verifier 解析最终答案：正确给 1，错误给 0。它只负责评价这次已经完成的回答，不告诉模型应该输出哪个 token。

第四步：调整模型。

训练希望：

  • 得到高分的回答，以后更容易被模型生成；
  • 得到低分的回答，以后更不容易被模型生成。

现在给第二步产生的对象一个名字：当前模型独立采样出的一条完整回答叫一次 rollout。rollout 不是标准答案，也不是固定训练数据；模型参数改变后，下一批 rollout 也会改变。

这点与监督微调非常不同。监督微调的数据在训练前已经写好；这里的回答是当前模型现场产生的。

1.2 一次生成中，模型究竟做了哪些选择

为了便于阅读，下面暂时把多个真实 token 合并成一个文本片段。实际语言模型仍然每次生成一个 tokenizer token。

生成时刻 模型已经看到的内容 本次生成的片段
1 prompt 17×20=340；
2 prompt + 第一段 17×3=51；
3 prompt + 前两段 所以答案是391。<eos>

每一行都发生同一件事：

  1. 模型读取 prompt 和已经生成的前缀；
  2. 输出下一个 token 的概率分布；
  3. 从分布中采样一个 token；
  4. 把该 token 追加到前缀，再进入下一步。

现在再给这些已经出现的对象命名。

当前前缀叫状态。

第 ttt 次生成之前的完整上下文记作 sts_tst​。在 LLM 中：

st=prompt+已经生成的 token 前缀.s_t=\text{prompt}+\text{已经生成的 token 前缀}.st​=prompt+已经生成的 token 前缀.

字母 sss 来自 state。下标 ttt 只表示当前是第几个生成位置。

本次采样的下一个 token 叫动作。

在状态 sts_tst​ 下采样出的 token 记作 ata_tat​。字母 aaa 来自 action。

模型给出的 next-token 分布叫策略。

正在训练的模型参数记作 θ\thetaθ。模型在前缀 sts_tst​ 下给下一个 token 的分布写作：

πθ(at∣st).\pi_\theta(a_t\mid s_t).πθ​(at​∣st​).

这句话只表示：

参数为 θ\thetaθ 的语言模型看到前缀 sts_tst​ 后，给实际采样 token ata_tat​ 分配的概率。

π\piπ 是策略的惯用字母，不表示新的网络；它就是当前语言模型的 next-token softmax。

追加 token 后得到新前缀。

执行动作后：

st+1=st+at.s_{t+1}=s_t+a_t.st+1​=st​+at​.

右边的加号表示字符串或 token 序列拼接，不是数值相加。对纯文本生成，这个状态变化通常是确定的。

现在才可以把对应关系压成一张表：

决策过程中的对象 LLM 中的具体含义
状态 sts_tst​ prompt + 已生成前缀
动作 ata_tat​ 下一个 token
策略 πθ\pi_\thetaπθ​ 当前语言模型的 next-token 分布

为什么必须保留整个前缀作为状态？因为模型下一步怎样分配概率，取决于此前已经写了什么。若只记“当前是第几个 token”，信息就不够。

1.3 一整条回答出现的概率从哪里来

先定义这一节需要的记号：

  • xxx：给定的 prompt；
  • yty_tyt​：回答中的第 ttt 个 token；
  • y<ty_{<t}y<t​：第 ttt 个 token 之前已经生成的所有 token；
  • TTT：这条回答的 token 数；
  • y1:Ty_{1:T}y1:T​：从第一个到第 TTT 个 token 组成的完整回答。

这只是把上一节的决策记号换成语言模型常用写法：

st=(x,y<t),at=yt.s_t=(x,y_{<t}),\qquad a_t=y_t.st​=(x,y<t​),at​=yt​.

模型生成完整回答，实际上是连续做 TTT 次条件采样：

先在 prompt 后采样 y₁
→ 再在 prompt + y₁ 后采样 y₂
→ 再在 prompt + y₁ + y₂ 后采样 y₃
→ 直到回答结束

把当前模型在 prompt xxx 下生成完整回答 y1:Ty_{1:T}y1:T​ 的概率记作 pθ(y1:T∣x)p_\theta(y_{1:T}\mid x)pθ​(y1:T​∣x)。乘积符号 ∏\prod∏ 表示把一组因子依次相乘。

根据概率的链式法则，完整回答的条件概率等于每一步条件概率的乘积：

pθ(y1:T∣x)=∏t=1Tπθ(yt∣x,y<t).p_\theta(y_{1:T}\mid x) = \prod_{t=1}^{T} \pi_\theta(y_t\mid x,y_{<t}).pθ​(y1:T​∣x)=t=1∏T​πθ​(yt​∣x,y<t​).

公式从左到右这样读：

  • pθ(y1:T∣x)p_\theta(y_{1:T}\mid x)pθ​(y1:T​∣x)：当前模型面对 prompt xxx 时生成整条回答 y1:Ty_{1:T}y1:T​ 的概率；
  • ∏\prod∏：把每个生成位置的概率相乘；
  • πθ(yt∣x,y<t)\pi_\theta(y_t\mid x,y_{<t})πθ​(yt​∣x,y<t​)：在实际前缀下生成实际 token yty_tyt​ 的概率。

用三个合并片段做一个纯数值例子。每个片段的概率，本身是片段内部各 token 条件概率的乘积；这里只把它压成一个数字。假设三个片段的条件概率依次为：

0.60,0.50,0.80.0.60,\qquad0.50,\qquad0.80.0.60,0.50,0.80.

那么这条完整回答出现的概率为：

0.60×0.50×0.80=0.24.0.60\times0.50\times0.80=0.24.0.60×0.50×0.80=0.24.

只要其中某一步的概率变小，整条回答的概率也会变小。训练语言模型的可控入口正是这些逐步条件概率。

一整次从 prompt 开始、直到回答结束的状态与动作序列叫轨迹，记作 τ\tauτ（希腊字母 tau）。在当前 LLM 任务中，可以直接把它读成：

τ=prompt + 一条完整生成回答.\tau=\text{prompt + 一条完整生成回答}.τ=prompt + 一条完整生成回答.

因此 pθ(τ∣x)p_\theta(\tau\mid x)pθ​(τ∣x) 只是“当前模型在 prompt xxx 下生成这条回答的概率”的简写，没有多出一个新的概率来源。

1.4 训练到底要让哪个数字变大

现在一条回答已经生成完，可以交给 verifier。

对于乘法题，最简单的评分规则是：

score = 1.0 if parsed_answer == 391 else 0.0

评分发生在回答结束之后。但在更一般的环境中，也可能在中间步骤给分，例如工具调用成功、格式合法或到达某个子目标。

把第 ttt 步之后立即得到的分数记作 rtr_trt​。字母 rrr 来自 reward（奖励）。 在只有最终评分的三步例子中：

r1=0,r2=0,r3=1.r_1=0,\qquad r_2=0,\qquad r_3=1.r1​=0,r2​=0,r3​=1.

一条轨迹从开始到结束实际得到的总分叫回报。用大写 R(τ)R(\tau)R(τ) 表示整条轨迹的回报。

如果要允许较晚的 reward 权重逐步衰减，先选一个 γ∈(0,1]\gamma\in(0,1]γ∈(0,1] 作为每向后一步的折扣比例，再计算：

R(τ)=∑t=1Tγt−1rt.R(\tau) = \sum_{t=1}^{T}\gamma^{t-1}r_t.R(τ)=t=1∑T​γt−1rt​.

γ\gammaγ 读作 gamma。短 LLM 回答和只有终局评分的任务中，常先取 γ=1\gamma=1γ=1，此时 R(τ)R(\tau)R(τ) 就是所有即时 reward 的直接相加。正确轨迹得到 1，错误轨迹得到 0。

一次采样可能碰巧成功或失败。训练真正想提高的不是某一条回答的分数，而是：

当前模型在训练 prompt 上反复生成时，平均能得到的回报。

现在再给这个平均目标命名。

  • D\mathcal DD：训练 prompt 的来源；可以理解为题库上的采样分布；
  • x∼Dx\sim\mathcal Dx∼D：从题库中抽取 prompt；
  • τ∼pθ(⋅∣x)\tau\sim p_\theta(\cdot\mid x)τ∼pθ​(⋅∣x)：当前模型在该 prompt 下采样一条回答；
  • E\mathbb EE：对许多可能的 prompt 和回答取平均；
  • J(θ)J(\theta)J(θ)：参数为 θ\thetaθ 的模型目前的平均训练表现。

目标写成：

J(θ)=Ex∼D,  τ∼pθ(⋅∣x)[R(τ)].J(\theta) = \mathbb E_{ x\sim\mathcal D,\; \tau\sim p_\theta(\cdot\mid x) } \left[ R(\tau) \right].J(θ)=Ex∼D,τ∼pθ​(⋅∣x)​[R(τ)].

如果一个固定 prompt 下，当前模型有 30% 概率答对、70% 概率答错，那么 0/1 评分下的平均回报就是：

0.30×1+0.70×0=0.30.0.30\times1+0.70\times0=0.30.0.30×1+0.70×0=0.30.

训练希望改变模型参数，让正确回答的概率上升，从而让这个平均值上升。

1.5 为什么这不是普通的有标签监督学习

把它和监督微调放在一起看：

监督微调 当前问题
回答从哪里来 数据集中的固定专家答案 当前模型现场采样
反馈是什么 每个位置的目标 token 整条回答或环境行为的分数
直接训练目标 模仿给定 token 改变不同回答被采到的概率
模型更新后数据是否变化 原数据不变 下一批回答随模型变化

不能把 verifier 的 1 当成“下一个 token 的类别标签”。它没有告诉模型：

  • 哪一个位置开始做对了；
  • 错误回答应该改成哪个 token；
  • 是否存在多种同样正确的答案。

当前 token 还会改变后面能看见的前缀。比如模型第二步把 51 写成 41，后续状态已经变成包含错误数字的上下文，之后的生成分布也会随之改变。

这种问题的结构是：

  1. 在当前状态下选择动作；
  2. 动作改变下一个状态；
  3. 若干步后得到 reward；
  4. 目标是让长期平均回报变高。

当状态保留了预测未来所需的信息时，这类顺序决策问题叫 Markov decision process（马尔可夫决策过程，MDP）。

对当前 LLM 任务，不需要先背一个抽象六元组。只要牢牢记住：

状态=完整前缀,动作=下一个 token,策略=语言模型,reward=外部评分.\text{状态=完整前缀},\qquad \text{动作=下一个 token},\qquad \text{策略=语言模型},\qquad \text{reward=外部评分}.状态=完整前缀,动作=下一个 token,策略=语言模型,reward=外部评分.

第一章到这里完成了四件事：

  1. 看清一次 rollout 是当前模型逐 token 采样出的回答；
  2. 把状态、动作和策略逐一对应到 LLM；
  3. 把整条回答概率写成逐 token 条件概率的乘积；
  4. 把训练目标写成当前模型的平均回报。

下一章只解决剩下的计算问题：

verifier 可以给离散回答打分，但采样出的 token id 本身不能对模型参数求导。怎样利用这个分数，改变产生这些 token 的概率？

这就是第二章推导的起点。

第二章：REINFORCE —— 让高回报轨迹更可能出现

本章问题：不能对采样出来的 token 求导，怎样把 reward 变成模型参数的梯度？

2.1 关键技巧：log-derivative trick

目标是调整模型参数 θ\thetaθ，让高回报轨迹更容易被采到。困难在于 τ\tauτ 是离散采样结果，不能把 token id 对 θ\thetaθ 直接求导。解决办法不是“对 token 求导”，而是对产生该 token 的概率求导。

下面从目标函数逐行推导。为便于阅读，先把轨迹看成离散变量；连续情形只是把求和换成积分。

第一步：把期望写成“所有轨迹的概率加权和”

J(θ)=Eτ∼pθ[R(τ)]=∑τpθ(τ)R(τ).J(\theta) =\mathbb E_{\tau\sim p_\theta}[R(\tau)] =\sum_\tau p_\theta(\tau)R(\tau).J(θ)=Eτ∼pθ​​[R(τ)]=τ∑​pθ​(τ)R(τ).

这里假设一次策略更新期间 reward 函数是固定的，因此 R(τ)R(\tau)R(τ) 不直接依赖 θ\thetaθ。对 θ\thetaθ 求导：

∇θJ(θ)=∑τR(τ)∇θpθ(τ).\nabla_\theta J(\theta) =\sum_\tau R(\tau)\nabla_\theta p_\theta(\tau).∇θ​J(θ)=τ∑​R(τ)∇θ​pθ​(τ).

到这里的问题是：我们想用采样估计这个梯度，但式子里只有 ∇θpθ(τ)\nabla_\theta p_\theta(\tau)∇θ​pθ​(τ)，还没有概率权重 pθ(τ)p_\theta(\tau)pθ​(τ)。

第二步：由链式法则得到 log-derivative trick

对任意正概率 pθ(τ)>0p_\theta(\tau)>0pθ​(τ)>0：

∇θlog⁡pθ(τ)=1pθ(τ)∇θpθ(τ).\nabla_\theta\log p_\theta(\tau) =\frac{1}{p_\theta(\tau)}\nabla_\theta p_\theta(\tau).∇θ​logpθ​(τ)=pθ​(τ)1​∇θ​pθ​(τ).

两边乘以 pθ(τ)p_\theta(\tau)pθ​(τ)，得到：

∇θpθ(τ)=pθ(τ)∇θlog⁡pθ(τ).\nabla_\theta p_\theta(\tau) =p_\theta(\tau)\nabla_\theta\log p_\theta(\tau).∇θ​pθ​(τ)=pθ​(τ)∇θ​logpθ​(τ).

这不是一个额外假设，只是 ∇log⁡p=(1/p)∇p\nabla\log p=(1/p)\nabla p∇logp=(1/p)∇p 的移项。将它代回上一步：

∇θJ(θ)=∑τpθ(τ)R(τ)∇θlog⁡pθ(τ)=Eτ∼pθ[R(τ)∇θlog⁡pθ(τ)].\begin{aligned} \nabla_\theta J(\theta) &=\sum_\tau p_\theta(\tau)R(\tau) \nabla_\theta\log p_\theta(\tau)\\ &=\mathbb E_{\tau\sim p_\theta} \left[R(\tau)\nabla_\theta\log p_\theta(\tau)\right]. \end{aligned}∇θ​J(θ)​=τ∑​pθ​(τ)R(τ)∇θ​logpθ​(τ)=Eτ∼pθ​​[R(τ)∇θ​logpθ​(τ)].​

现在式子重新变成了一个期望，所以可以用模型实际采出的 rollout 做 Monte Carlo 估计。

第三步：把“整条回答的 log 概率”拆成每一步

第一章已经从 LLM 的实际生成过程得到：

pθ(τ∣x)=∏t=1Tπθ(at∣st).p_\theta(\tau\mid x) = \prod_{t=1}^{T} \pi_\theta(a_t\mid s_t).pθ​(τ∣x)=t=1∏T​πθ​(at​∣st​).

这里固定当前 prompt xxx；sts_tst​ 已经包含 prompt 和生成前缀，ata_tat​ 是实际采样的 token。乘积取对数后变成求和：

log⁡pθ(τ∣x)=∑t=1Tlog⁡πθ(at∣st).\log p_\theta(\tau\mid x) = \sum_{t=1}^{T} \log\pi_\theta(a_t\mid s_t).logpθ​(τ∣x)=t=1∑T​logπθ​(at​∣st​).

因此，对模型参数 θ\thetaθ 求梯度：

∇θlog⁡pθ(τ∣x)=∑t=1T∇θlog⁡πθ(at∣st).\nabla_\theta\log p_\theta(\tau\mid x) = \sum_{t=1}^{T} \nabla_\theta\log\pi_\theta(a_t\mid s_t).∇θ​logpθ​(τ∣x)=t=1∑T​∇θ​logπθ​(at​∣st​).

这一步不再需要额外的初始状态分布或环境转移符号。prompt 来自固定训练题库，追加 token 也不包含可训练参数；模型能够改变的只有每一步 next-token 概率。

代回目标函数，得到策略梯度：

∇θJ(θ)=Eτ∼pθ[R(τ)∑t=1T∇θlog⁡πθ(at∣st)]\boxed{ \nabla_\theta J(\theta) = \mathbb E_{\tau\sim p_\theta} \left[ R(\tau) \sum_{t=1}^{T} \nabla_\theta\log\pi_\theta(a_t\mid s_t) \right] }∇θ​J(θ)=Eτ∼pθ​​[R(τ)t=1∑T​∇θ​logπθ​(at​∣st​)]​

如果采样 NNN 条 rollout，期望可用样本平均近似：

∇θJ(θ)≈1N∑i=1NR(τ(i))∑t=1Ti∇θlog⁡πθ(at(i)∣st(i)).\nabla_\theta J(\theta) \approx \frac{1}{N}\sum_{i=1}^{N} R(\tau^{(i)}) \sum_{t=1}^{T_i} \nabla_\theta\log\pi_\theta (a_t^{(i)}\mid s_t^{(i)}).∇θ​J(θ)≈N1​i=1∑N​R(τ(i))t=1∑Ti​​∇θ​logπθ​(at(i)​∣st(i)​).

完整逻辑链现在是：

最大化模型反复生成时的平均回报
→ 把平均值展开成“每条回答的概率 × 它的回报”
→ 用 ∇log p = (1/p)∇p 改写成可以用采样估计的期望
→ 把整条回答的 log 概率拆成逐 token log 概率之和

2.2 一条 rollout 如何变成可训练的 loss

2.1 得到的是一个期望：

∇θJ(θ)=E[R(τ)∑t∇θlog⁡πθ(at∣st)].\nabla_\theta J(\theta) =\mathbb E\left[ R(\tau)\sum_t\nabla_\theta\log\pi_\theta(a_t\mid s_t) \right].∇θ​J(θ)=E[R(τ)t∑​∇θ​logπθ​(at​∣st​)].

训练时不可能枚举所有回答，只能让模型采样一批 rollout，用样本平均近似这个期望。对第 iii 条 rollout，我们已经保存了每个位置实际生成 token 的 logp，现在还缺一个问题：第 ttt 个 token 应该由哪些奖励负责？

动作 ata_tat​ 只能影响它发生之后的结果，不能影响过去已经拿到的奖励。因此给它使用从时刻 ttt 开始的累计回报。

这个量叫 reward-to-go，记作 GtG_tGt​：大写 GGG 是回报的惯用记号， 下标 ttt 表示从第 ttt 步开始计算；它不是一个新的 reward model。 定义为：

它执行的不是复杂算法，只是一条因果规则：

第 t 个 token 的训练权重
= 当前奖励 + 折扣后的未来奖励

如果奖励只在回答结束时给出，那么同一条回答中的各个 GtG_tGt​ 都由终点 reward 传播而来；若中间还有过程奖励或格式奖励，不同位置的 GtG_tGt​ 就会不同。

用 NNN 条 rollout 近似期望，并把梯度上升改写成深度学习框架使用的梯度下降，得到一个可最小化的 loss。

现在才给它命名：L\mathcal LL 表示 loss，下标 REINFORCE 表示这是刚才推导出的 REINFORCE loss；NNN 是本批 rollout 数量。因此：

  2. GtG_tGt​ 表示该 token 之后实际发生了多好的结果；
  3. 前面的负号把“最大化期望回报”转换为“最小化 loss”；
  4. batch 和 token 维度最后取平均，padding 与 prompt 位置用 mask 排除。

2.4 回到乘法题：原始 REINFORCE 学到了什么

假设模型目前只会生成两种答案：

回答 当前概率 verifier reward
A：391 0.300.300.30 111
B：381 0.700.700.70 000

如果本批采到 A，终点 reward 为 111，这条回答中的采样 token 获得正权重，A 的概率会上升。如果采到 B，reward 为 000，权重也是 000，这一条样本不更新策略。

反复采样后，A 一旦出现就会被增强，因此正确率仍然能够从 0.300.300.30 往上走。这说明 REINFORCE 已经解决了最基本的问题：即使正确答案不是监督标签，只要模型偶尔采到并获得奖励，也能提高它再次出现的概率。

但这个例子也暴露出两个结构性缺陷：

  1. 零分不是负反馈。 B 得到 000 时只是没有更新，不会被直接压低；
  2. 绝对分数没有参照系。 同样得到 111 分，可能是简单题上的正常发挥，也可能是难题上的罕见成功，却会得到相同权重。

如果奖励只在终点出现，整条回答中的 token 还会共享非常相似的回报信号，credit assignment 也很粗。原始 REINFORCE 因而“能学”，但样本效率和稳定性都不理想。

2.5 REINFORCE 与 SFT 的差别

两者的代码表面都包含 -weight * logprob，但数据来源与优化含义不同：

SFT 原始 REINFORCE
token 来自人类或离线参考答案 token 来自当前模型自己的 rollout
每个目标 token 通常都用正的 mask 权重 权重来自实际观察到的 reward-to-go
目标是复现给定答案 目标是改变采样分布、提高期望 reward
本轮数据不由当前模型生成 模型一更新，下一批 rollout 分布就会变化

因此 REINFORCE 不是“给 SFT 交叉熵乘一个 reward”这么简单。它的训练数据来自策略自身，reward 又带有很强的随机性；后续方法都在处理由此产生的方差、信用分配和数据过期问题。

Value 网络实际怎样学？

真实训练不会为每个前缀额外分叉采样 10 次，那样太贵。实际做法是：

  1. 当前策略正常生成一批完整回答；
  2. verifier 给每条回答最终打分；
  3. 一次成功 rollout 为沿途每个前缀提供一次“未来回报为 1”的样本，失败 rollout 提供一次“未来回报为 0”的样本；
  4. 用很多 rollout 训练一个神经网络 Vϕ(s)V_\phi(s)Vϕ​(s)，让它预测这些未来回报；
  5. 神经网络在相似 prompt 和相似前缀之间泛化，近似刚才昂贵的重复采样平均值。

最简单的训练目标就是平方误差：

LV(ϕ)=Et[(Vϕ(st)−Gt)2].\mathcal L_V(\phi) = \mathbb E_t\left[ \left(V_\phi(s_t)-G_t\right)^2 \right].LV​(ϕ)=Et​[(Vϕ​(st​)−Gt​)2].

在 LLM 中，通常把前缀送进因果 Transformer，再把对应位置的隐藏向量通过一个线性 value head，输出一个标量。一次完整前向可以同时得到各个 token 前缀的 value。

课程里把这个 value 预测网络叫 critic。它不是答案评分器：

  • verifier / reward model 负责评价已经完成的答案；
  • critic 负责预测尚未完成的前缀，按当前策略继续生成后通常能拿多少分。

  • A^t<0\widehat A_t<0At​<0：这次比预期差，降低所采样 token 的概率。

但 Gt−V(st)G_t-V(s_t)Gt​−V(st​) 仍然要等整条回答结束。接下来把它拆成相邻前缀之间的修正。

3.4 怎样把终局修正传回更早的 token

有两个极端：

  • 只用当前一步的 δt\delta_tδt​：信号局部、波动较小，但过度相信 critic；
  • 把后面所有 δ\deltaδ 全部加回来：能得到完整的 Gt−V(st)G_t-V(s_t)Gt​−V(st​)，但长回答上的样本波动更大。

可以在两者之间做平滑折中：让相邻下一步的修正保留较大权重，距离越远，权重越小。 用 λ∈[0,1]\lambda\in[0,1]λ∈[0,1] 表示每向前传播一步时额外保留的比例：

  • 距离当前步越远，修正会多乘几次 γλ\gamma\lambdaγλ；

  • 正确回答的终局正修正向前传播，三个片段都得到正权重；
  • 错误回答的终局负修正向前传播，抵消 critic 先前的错误乐观；

  • terminated[t]：生成后是否真正终止。

它只是一个乘法开关，不是新的强化学习量。完整递推为：

# old_value:          [T + 1]

    continue_mask = 1.0 - terminated[t]

    delta = (
        reward[t]
        + gamma * old_value[t + 1] * continue_mask
        - old_value[t]
    )
    gae = (
        delta
        + gamma * lam * continue_mask * gae
    )
    advantage[t] = gae

advantage 给策略模型使用。它表示目标相对旧 value 高多少或低多少；把旧 value 加回去，就得到 critic 要拟合的绝对目标 value_target。

还要区分三种边界：

  • 真正终止：生成 EOS，或任务明确成功/失败，continue_mask = 0；
  • 达到最大长度而截断：任务理论上可能继续；若保留最后状态的 value，通常仍应 bootstrap，不能自动当成真正终止；
  • padding：只是 batch 对齐产生的填充 token，应由单独的 response mask 排除。

第四章：同一批 rollout 为什么不能随便多训
