# 第一周：从“给回答打分”到“稳定更新语言模型”

> 适用对象：熟悉深度学习、Transformer 和基本概率论，但没有系统学过强化学习的算法工程师。
>
> 正文可以脱离 slides 独立阅读。第一章不预设强化学习术语；公式中的符号会在公式之前逐个解释。

本周只研究一条训练链：

> 语言模型自己生成回答，外部系统给回答打分；我们根据这些分数调整模型，同时限制一次更新不要走得过远。

各章依次回答：

1. 一条回答是怎样逐步生成、怎样被评分的？
2. 最终分数怎样改变已生成 token 的概率？
3. 怎样判断某个 token 的表现高于还是低于正常水平？
4. 怎样有限复用同一批回答，同时避免模型变化过大？
5. 这些计算在一次真实训练迭代中按什么顺序发生？

贯穿本周的 prompt 是：

```text
计算 17 × 23，并给出简短推理。
```

这里的 verifier 是自动判题程序：它读取完整回答并检查最终结果是否正确。

模型可能生成：

| 回答 | verifier 评分 |
|---|---:|
| `17×20=340；17×3=51；所以答案是391。` | 1 |
| `17×20=340；17×3=41；所以答案是381。` | 0 |

我们不会把 1 或 0 伪装成 token 标签。真正的问题是：怎样让第一条回答以后更容易出现，让第二条回答以后更不容易出现？

# 第一章：模型怎样自己生成答案并从得分中学习

本章不从强化学习术语开始，只跟着一次语言模型生成过程走到底。读完后，你只需要能回答：

1. 模型在每个生成位置控制什么？
2. 一整条回答的概率为什么是逐 token 概率的乘积？
3. verifier 的一个最终分数怎样变成训练目标？
4. 为什么这个问题不是普通的有标签监督学习？

## 1.1 先看一轮训练实际发生了什么

忽略算法名称，一轮最小训练过程只有四步。

**第一步：取一道题。**

从训练题库取得一个 prompt：

```text
计算 17 × 23，并给出简短推理。
```

**第二步：让当前模型自己生成。**

模型不是读取标准答案，而是根据自己的 next-token 概率逐步采样。一次可能生成正确回答，另一次也可能生成错误回答。

**第三步：生成结束后评分。**

verifier 解析最终答案：正确给 1，错误给 0。它只负责评价这次已经完成的回答，不告诉模型应该输出哪个 token。

**第四步：调整模型。**

训练希望：

- 得到高分的回答，以后更容易被模型生成；
- 得到低分的回答，以后更不容易被模型生成。

现在给第二步产生的对象一个名字：**当前模型独立采样出的一条完整回答叫一次
rollout**。rollout 不是标准答案，也不是固定训练数据；模型参数改变后，下一批 rollout
也会改变。

这点与监督微调非常不同。监督微调的数据在训练前已经写好；这里的回答是当前模型现场产生的。

## 1.2 一次生成中，模型究竟做了哪些选择

为了便于阅读，下面暂时把多个真实 token 合并成一个文本片段。实际语言模型仍然每次生成一个 tokenizer token。

| 生成时刻 | 模型已经看到的内容 | 本次生成的片段 |
|---:|---|---|
| 1 | prompt | `17×20=340；` |
| 2 | prompt + 第一段 | `17×3=51；` |
| 3 | prompt + 前两段 | `所以答案是391。<eos>` |

每一行都发生同一件事：

1. 模型读取 prompt 和已经生成的前缀；
2. 输出下一个 token 的概率分布；
3. 从分布中采样一个 token；
4. 把该 token 追加到前缀，再进入下一步。

现在再给这些已经出现的对象命名。

**当前前缀叫状态。**

第 \(t\) 次生成之前的完整上下文记作 \(s_t\)。在 LLM 中：

\[
s_t=\text{prompt}+\text{已经生成的 token 前缀}.
\]

字母 \(s\) 来自 state。下标 \(t\) 只表示当前是第几个生成位置。

**本次采样的下一个 token 叫动作。**

在状态 \(s_t\) 下采样出的 token 记作 \(a_t\)。字母 \(a\) 来自 action。

**模型给出的 next-token 分布叫策略。**

正在训练的模型参数记作 \(\theta\)。模型在前缀 \(s_t\) 下给下一个 token 的分布写作：

\[
\pi_\theta(a_t\mid s_t).
\]

这句话只表示：

> 参数为 \(\theta\) 的语言模型看到前缀 \(s_t\) 后，给实际采样 token \(a_t\) 分配的概率。

\(\pi\) 是策略的惯用字母，不表示新的网络；它就是当前语言模型的 next-token softmax。

**追加 token 后得到新前缀。**

执行动作后：

\[
s_{t+1}=s_t+a_t.
\]

右边的加号表示字符串或 token 序列拼接，不是数值相加。对纯文本生成，这个状态变化通常是确定的。

现在才可以把对应关系压成一张表：

| 决策过程中的对象 | LLM 中的具体含义 |
|---|---|
| 状态 \(s_t\) | prompt + 已生成前缀 |
| 动作 \(a_t\) | 下一个 token |
| 策略 \(\pi_\theta\) | 当前语言模型的 next-token 分布 |
| 状态变化 | 把新 token 追加到前缀 |
| 结束条件 | 生成 EOS、达到任务终止条件或被长度限制截断 |

为什么必须保留整个前缀作为状态？因为模型下一步怎样分配概率，取决于此前已经写了什么。若只记“当前是第几个 token”，信息就不够。

## 1.3 一整条回答出现的概率从哪里来

先定义这一节需要的记号：

- \(x\)：给定的 prompt；
- \(y_t\)：回答中的第 \(t\) 个 token；
- \(y_{<t}\)：第 \(t\) 个 token 之前已经生成的所有 token；
- \(T\)：这条回答的 token 数；
- \(y_{1:T}\)：从第一个到第 \(T\) 个 token 组成的完整回答。

这只是把上一节的决策记号换成语言模型常用写法：

\[
s_t=(x,y_{<t}),\qquad a_t=y_t.
\]

模型生成完整回答，实际上是连续做 \(T\) 次条件采样：

```text
先在 prompt 后采样 y₁
→ 再在 prompt + y₁ 后采样 y₂
→ 再在 prompt + y₁ + y₂ 后采样 y₃
→ 直到回答结束
```

把当前模型在 prompt \(x\) 下生成完整回答 \(y_{1:T}\) 的概率记作
\(p_\theta(y_{1:T}\mid x)\)。乘积符号 \(\prod\) 表示把一组因子依次相乘。

根据概率的链式法则，完整回答的条件概率等于每一步条件概率的乘积：

\[
p_\theta(y_{1:T}\mid x)
=
\prod_{t=1}^{T}
\pi_\theta(y_t\mid x,y_{<t}).
\]

公式从左到右这样读：

- \(p_\theta(y_{1:T}\mid x)\)：当前模型面对 prompt \(x\) 时生成整条回答
  \(y_{1:T}\) 的概率；
- \(\prod\)：把每个生成位置的概率相乘；
- \(\pi_\theta(y_t\mid x,y_{<t})\)：在实际前缀下生成实际 token \(y_t\) 的概率。

用三个合并片段做一个纯数值例子。每个片段的概率，本身是片段内部各 token
条件概率的乘积；这里只把它压成一个数字。假设三个片段的条件概率依次为：

\[
0.60,\qquad0.50,\qquad0.80.
\]

那么这条完整回答出现的概率为：

\[
0.60\times0.50\times0.80=0.24.
\]

只要其中某一步的概率变小，整条回答的概率也会变小。训练语言模型的可控入口正是这些逐步条件概率。

一整次从 prompt 开始、直到回答结束的状态与动作序列叫**轨迹**，记作
\(\tau\)（希腊字母 tau）。在当前 LLM 任务中，可以直接把它读成：

\[
\tau=\text{prompt + 一条完整生成回答}.
\]

因此 \(p_\theta(\tau\mid x)\) 只是“当前模型在 prompt \(x\) 下生成这条回答的概率”的简写，没有多出一个新的概率来源。

## 1.4 训练到底要让哪个数字变大

现在一条回答已经生成完，可以交给 verifier。

对于乘法题，最简单的评分规则是：

```python
score = 1.0 if parsed_answer == 391 else 0.0
```

评分发生在回答结束之后。但在更一般的环境中，也可能在中间步骤给分，例如工具调用成功、格式合法或到达某个子目标。

把第 \(t\) 步之后立即得到的分数记作 \(r_t\)。字母 \(r\) 来自 reward（奖励）。
在只有最终评分的三步例子中：

\[
r_1=0,\qquad r_2=0,\qquad r_3=1.
\]

一条轨迹从开始到结束实际得到的总分叫**回报**。用大写 \(R(\tau)\) 表示整条轨迹的回报。

如果要允许较晚的 reward 权重逐步衰减，先选一个
\(\gamma\in(0,1]\) 作为每向后一步的折扣比例，再计算：

\[
R(\tau)
=
\sum_{t=1}^{T}\gamma^{t-1}r_t.
\]

\(\gamma\) 读作 gamma。短 LLM 回答和只有终局评分的任务中，常先取
\(\gamma=1\)，此时 \(R(\tau)\) 就是所有即时 reward 的直接相加。正确轨迹得到 1，错误轨迹得到 0。

一次采样可能碰巧成功或失败。训练真正想提高的不是某一条回答的分数，而是：

> 当前模型在训练 prompt 上反复生成时，平均能得到的回报。

现在再给这个平均目标命名。

- \(\mathcal D\)：训练 prompt 的来源；可以理解为题库上的采样分布；
- \(x\sim\mathcal D\)：从题库中抽取 prompt；
- \(\tau\sim p_\theta(\cdot\mid x)\)：当前模型在该 prompt 下采样一条回答；
- \(\mathbb E\)：对许多可能的 prompt 和回答取平均；
- \(J(\theta)\)：参数为 \(\theta\) 的模型目前的平均训练表现。

目标写成：

\[
J(\theta)
=
\mathbb E_{
x\sim\mathcal D,\;
\tau\sim p_\theta(\cdot\mid x)
}
\left[
R(\tau)
\right].
\]

如果一个固定 prompt 下，当前模型有 30% 概率答对、70% 概率答错，那么 0/1
评分下的平均回报就是：

\[
0.30\times1+0.70\times0=0.30.
\]

训练希望改变模型参数，让正确回答的概率上升，从而让这个平均值上升。

后文有时会把“先从题库抽 prompt，再让模型生成回答”合并写成
\(\tau\sim p_\theta\)。这只是省略书写，仍然包含上面两层采样。

## 1.5 为什么这不是普通的有标签监督学习

把它和监督微调放在一起看：

| | 监督微调 | 当前问题 |
|---|---|---|
| 回答从哪里来 | 数据集中的固定专家答案 | 当前模型现场采样 |
| 反馈是什么 | 每个位置的目标 token | 整条回答或环境行为的分数 |
| 直接训练目标 | 模仿给定 token | 改变不同回答被采到的概率 |
| 模型更新后数据是否变化 | 原数据不变 | 下一批回答随模型变化 |

不能把 verifier 的 `1` 当成“下一个 token 的类别标签”。它没有告诉模型：

- 哪一个位置开始做对了；
- 错误回答应该改成哪个 token；
- 是否存在多种同样正确的答案。

当前 token 还会改变后面能看见的前缀。比如模型第二步把 `51` 写成 `41`，后续状态已经变成包含错误数字的上下文，之后的生成分布也会随之改变。

这种问题的结构是：

1. 在当前状态下选择动作；
2. 动作改变下一个状态；
3. 若干步后得到 reward；
4. 目标是让长期平均回报变高。

当状态保留了预测未来所需的信息时，这类顺序决策问题叫
**Markov decision process（马尔可夫决策过程，MDP）**。

对当前 LLM 任务，不需要先背一个抽象六元组。只要牢牢记住：

\[
\text{状态=完整前缀},\qquad
\text{动作=下一个 token},\qquad
\text{策略=语言模型},\qquad
\text{reward=外部评分}.
\]

第一章到这里完成了四件事：

1. 看清一次 rollout 是当前模型逐 token 采样出的回答；
2. 把状态、动作和策略逐一对应到 LLM；
3. 把整条回答概率写成逐 token 条件概率的乘积；
4. 把训练目标写成当前模型的平均回报。

> verifier 可以给离散回答打分，但采样出的 token id 本身不能对模型参数求导。怎样利用这个分数，改变产生这些 token 的概率？

这就是第二章推导的起点。
